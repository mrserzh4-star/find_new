Повну спеку за форматом брифу не наводжу свідомо: контракт даних недосяжний, описувати нема чого. Нижче — що саме перевірено і чим замінити.

## 1. Спосіб доступу — заблоковано

Попередній зріз (15.07) казав «SPA з шаблонами `{{vacancy.title}}`». Станом на 27.07 картина інша: **весь домен за Cloudflare managed challenge**.

```
GET https://career.pumb.ua/vacancy
→ HTTP 403 Forbidden
   Cf-Mitigated: challenge
   Server: cloudflare
   Content-Type: text/html  (сторінка «Just a moment…»)
```

Заблоковано **не окремий шлях, а домен цілком** — перевірено чотири різні URL:

| URL | Результат |
|---|---|
| `career.pumb.ua/vacancy` | 403 challenge |
| `career.pumb.ua/` | 403 challenge |
| `career.pumb.ua/robots.txt` | 403 challenge |
| `career.pumb.ua/api/vacancy` | 403 challenge |

Те, що навіть `robots.txt` за челенджем — показник: це не фільтр за User-Agent, а суцільний захист периметра. Підміна UA не допомагає (перевірено з повним Chrome-UA).

### Перевірка справжнім браузером

Відкрив `career.pumb.ua/vacancy` у реальному Chrome (не headless, звичайний профіль користувача). Сторінка **залишилась на челенджі**:

Title: Один момент…

Челендж не самоочистився. Далі я не йшов: **обхід бот-детекту я не роблю** — це і поза межами задачі, і те, чого я не робитиму за жодних умов. Тому Network-контракт (внутрішній API, поля, пагінація) залишається **невідомим**, і я не буду вигадувати його з попередніх спостережень.

## 6. Ризики

Не «ризики адаптера», а причина відмови:

- Cloudflare managed challenge потребує виконання JS-челенджу з валідним браузерним відбитком. `httpx` не пройде ніколи.
- Playwright **може** пройти, а може й ні — managed challenge регулярно детектить автоматизацію. Це гонитва озброєнь: працює до наступного оновлення правил Cloudflare, після чого адаптер мовчки віддає 403 щогодини.
- Ціна: Playwright тягне ~400 МБ браузера в CI. Для **однієї** компанії — неспівмірно.
- На GitHub Actions (наш обраний хостинг) IP-діапазони дата-центрів Cloudflare оцінює гірше за домашні — ймовірність блоку там вища, ніж у моєму тесті.

## 7. ✅ Обхідний шлях: PUMB уже є на DOU — безкоштовно

PUMB дублює свої вакансії на DOU під слагом компанії **`fuib`** (First Ukrainian International Bank). Перевірено запитом:

```
https://jobs.dou.ua/vacancies/feeds/?search=%D0%9F%D0%A3%D0%9C%D0%91
```

Реальний результат (27.07.2026), 3 вакансії:

```
Middle II Flutter Developer в ПУМБ (First Ukrainian International Bank), $3500–4000, за кордоном, віддалено
  https://jobs.dou.ua/companies/fuib/vacancies/340963/
Middle+ Product Designer в ПУМБ (First Ukrainian International Bank), $3500–4000, за кордоном, віддалено
  https://jobs.dou.ua/companies/fuib/vacancies/344123/
Middle Java Developer в ПУМБ (First Ukrainian International Bank), $2800–3200, за кордоном, віддалено
  https://jobs.dou.ua/companies/fuib/vacancies/364458/
```

Серед них — **`Middle+ Product Designer`, тобто рівно цільовий профіль**, віддалено, із зарплатою. Саме та вакансія, заради якої PUMB узагалі в списку.

### Чого цей обхід НЕ дає

Чесно про обмеження:
- покриття неповне — на DOU потрапляє лише те, що PUMB САМ туди виклав (переважно IT-позиції). Банківські/не-IT ролі з `career.pumb.ua` залишаться поза межами;
- **фільтра по компанії у DOU-фіді немає**: параметр `?company=fuib` **мовчки ігнорується** (перевірено: HTTP 200, 50 записів, з них 0 стосуються fuib). Тому «ловити PUMB» можна лише через `?search=ПУМБ`, або просто не виділяти окремо — вакансія й так прилетить у загальний `category=Design`.

### Наслідок ширший за PUMB

Це, схоже, **загальний патерн для українських банків**: власна кар'єрка під захистом / SPA, але IT-вакансії продубльовані на DOU й Djinni. Якщо так, то ПриватБанк, монобанк, Ощадбанк тощо **окремих адаптерів не потребують взагалі** — їх покриває джоб-борд. Перевірю це в частині 2 (Djinni + ATS-групування) і підтверджу або спростую по кожному банку окремо.
