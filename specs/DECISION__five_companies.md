## 2. TechStack — двозначність знята, і не здогадом

DOU-сторінка `/companies/tech-stack/` вказує сайт:

Тобто **`tech-stack.com` — наша компанія**, `techstack.com` ні.

Додатково: `career.tech-stack.com/` і `tech-stack.com/career` віддають **той самий вміст** (148 КБ, 47 текстових рядків) — це одна кар'єрка під двома адресами, а не два різні сайти.

## 4. Greenwich — компанію не ідентифіковано, і я не вгадую

```
greenwich.com.ua/            HTTP 503  (перевірено вдруге, через ~15 хв)
greenwich.com.ua/robots.txt  HTTP 200
```

Robots віддається, і він **інтернет-магазинний**:
```
Disallow: /*route=account/
Disallow: /*route=checkout/
Disallow: /*route=product/compare
```
Це OpenCart. Тобто за цією адресою крамниця, а не IT-компанія з кар'єркою.

На DOU знайшлась `Greenwich IT Solutions recruitment company` — **рекрутингова агенція**, 0 вакансій, і назва не збігається.

**Отже маємо три різні «Greenwich» і жодного підтвердження, який із них потрібен власнику.** Не вибираю — потрібне уточнення від нього. Це рівно те місце, де я мало не приписав компанії чужі дані з `applyft.com`.

## 5. Дві пастки, на яких я мало не збудував відповідь

### `?search=` на DOU мовчки ігнорується

```
/companies/?search=Elephants   → 112 КБ, ті самі 31 компанія
/companies/?search=Neontri     → 112 КБ, ті самі 31 компанія
/companies/?search=TechStack   → 112 КБ, ті самі 31 компанія
```
Перший прогін дав «збігів немає» для всіх пʼяти — і це було **властивістю мого запиту**, не DOU. Справжній параметр зветься `name`.

Перевірив контролем, перш ніж вірити другому разу:
```
name=(порожньо)          31 компанія
name=zzzqqqxxxnonsense   12  ← базовий шум сторінки
name=Ciklum              14  ← параметр працює
```
Без цього контролю «12 компаній» читалось би як «знайшли 12».

### Хибний URL фіда віддає HTTP 200 і валідний ПОРОЖНІЙ RSS

Я взяв формат `/vacancies/feeds/company-<slug>/`. Він відповідає:
```
HTTP 200 · валідний RSS · <title>Вакансії за запитом «company-tech-stack»</title> · 0 items
```
DOU розібрав це як **пошуковий запит**, не знайшов нічого й чесно віддав порожній фід.

Спіймав контрольним слаґом:
```
raiffeisen через мій URL     → 0 вакансій
raiffeisen через URL проєкту → 22 вакансії
```
Правильний формат — `/vacancies/<slug>/feeds/`, як у `dou_companies.py:54`.

**Без контрольного слаґа я б доповів «у tech-stack вакансій немає», і це виглядало б переконливо** — валідний RSS, правильна назва компанії в заголовку, нуль записів.

## 6. Рекомендація

**Зробити:** додати `tech-stack` у `sources.dou_companies.slugs`. Один рядок.

**Не робити:** пʼять HTML-адаптерів. Вони дали б одну вакансію, польську й on-site, і кожен був би найкрихкішим типом джерела в проєкті — без ATS, без RSS, без JSON-LD.

**Спитати власника:** який саме Greenwich він мав на увазі.

**Переміряти згодом:** `elephantslab`, `beliketech`, `neontri` — компанії малі, вакансії зʼявляються рідко, і сьогоднішній нуль це число одного дня. Але переміряти дешевше вручну раз на місяць, ніж тримати три крихкі адаптери.
