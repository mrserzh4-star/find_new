## 🔴 Заборонені за robots.txt — не беремо, обхід не пропоную

Перевірено блок `User-agent: *` у кожного:

- **LinkedIn** — `Disallow: /` для всіх агентів. Тотальна заборона. Питання закрите.
- **Indeed** — `/job/`, `/Job/`, `/jobb/`, `/api/getrecjobs` заборонені. Тобто саме сторінки вакансій.
- **Glassdoor** — `/jobview/`, `/partners/jobs/` заборонені.
- **Wellfound** — `/_jobs/`, `/*?jobId=*`, `/*?jobSlug=*` заборонені.

Технічно вони, можливо, віддали б контент — але це прямо заборонено умовами, тож це чесне 🔴, як і просив бриф.

**Окремо про RemoteOK.** Його `robots.txt` НЕ забороняє `*`, але містить `Disallow: /` для списку ботів, серед яких **`ClaudeBot`**. Тобто мені як Claude краулити його не належить; скрипт власника — інший агент. Плюс їхній API має ToS: вимагає зворотне посилання й згадку RemoteOK як джерела. Але це академічне питання, бо якість даних все одно нікуди не годиться (див. нижче).

## 🔴 Cloudflare — недосяжні без обходу захисту

`robota.ua`, `Jooble`, `PUMB` — HTTP 403 з `Cf-Mitigated: challenge`. У PUMB заблоковано навіть `robots.txt`, і челендж не пройшов у справжньому Chrome. Обхід бот-детекту не будував і не пропоную.

**Behance JobList** — 403 на `/joblist`. Не Cloudflare-челендж, але доступу немає.

## 🔴 RemoteOK — доступний, але дані непридатні

API `https://remoteok.com/api` віддає HTTP 200, 325 КБ, 101 запис, структура чиста (`slug, id, epoch, date, company, position, tags, location, salary_min, salary_max, url`). Тобто технічно 🟢.

## Групування за платформою (ATS)

Знайдені **спільні платформи**, де один адаптер покриває багато джерел:

### 1. `schema.org JobPosting` (JSON-LD) — не ATS, а наскрізний стандарт
**Покриває: Djinni** (підтверджено) — і, ймовірно, більшість сучасних бордів.

Це найцінніша знахідка для архітектури: замість «парсер під кожен сайт» пишеться **один парсер JSON-LD**, а під кожне джерело — лише спосіб знайти список URL (RSS/API/sitemap). Розмітка стандартна, її тримають заради Google for Jobs, тому вона стабільніша за будь-яку верстку.

**Рекомендація `visual`:** зробити `jsonld_jobposting.py` окремим модулем від самого початку, а не всередині адаптера Djinni. Далі кожне нове джерело — це ~30 рядків «як дістати список посилань» + виклик спільного парсера.

### 2. WordPress REST API
**Покриває: HappyMonday** (підтверджено, тип запису `job`). Патерн масовий серед українських медіа/нішевих порталів — варто пробувати `"/wp-json/wp/v2/types"` на кожному новому кандидаті, це один дешевий запит.

### 3. RSS 2.0 / Atom
**Покриває: DOU, Djinni, We Work Remotely, Himalayas.** Один парсер, різні URL і словники категорій.

### ⚠️ Класичні ATS (Greenhouse / Lever / Workable / SmartRecruiters / Recruitee / Teamtailor) — **НЕ перевірено**
Це частина завдання, яку я **не встиг**. Вона прив'язана до розбору топ-50 компаній (див. нижче).
