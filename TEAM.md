# Команда проекта find_new (job-scraper → Telegram)

Канал координации: `_coord/` (Holonet, бэкенд `folder`). Доска: `_coord/ORCHESTRATOR.md`.

## Контракт ролей

| Роль | Кто владеет | Что делает |
|---|---|---|
| `coordinator` | эта сессия | Архитектура, единая схема данных, постановка задач (`coord delegate`), приёмка, сборка. **Сам не пилит.** |
| `researcher` | отдельная сессия | Разведка источников: по каждому сайту — есть ли RSS/API или это SPA; поиск реальных эндпоинтов; документирование контракта (поля, фильтры, пагинация, лимиты, анти-бот). Выход — спека адаптера, не код. |
| `visual` | отдельная сессия | **Исполнитель: бэкенд И фронтенд.** Пишет весь код сервиса (адаптеры, фильтр, дедуп, отправка в Telegram, расписание) + отвечает за то, как это выглядит: формат карточки вакансии в канале и фронт, если появится. |

> ⚠️ Роль `visual` вопреки названию отвечает за реализацию целиком — и за бэкенд тоже. Это решение владельца проекта (27.07.2026). Не сужать её до оформления.

## Протокол

- Каждая сессия пишет **только свою** строку в `_coord/inbox/<session_id>.md`. `FLAG.md` / `STATE.md` / `ROLES.md` / `ORCHESTRATOR.md` — генерируемые, руками не править.
- Постановка задачи: координатор → `coord delegate --to <role> "задача"`. Бриф собирается по шаблону: задача → контекст/источники → output-contract → правила.
- Отчёт: исполнитель → **одному получателю (`coordinator`)**, нумерованными next steps.
- Статус работы: `coord state working --doing "<что делаю>"` / `parked --last <ref>`. Видно координатору на доске.
- Прочитал сообщение → `coord ack <file>`. Иначе висит непрочитанным.
- Само-пробуждение на новые сообщения: `/tempus-os:holonet-monitor-start` (монитор умирает вместе с процессом — после рестарта сессии армить заново).
